# אתר מכירות כללי (Netlify) + פאנל ניהול + סליקה בטרנזילה

אתר חנות סטטי (HTML + CSS + JavaScript, בלי build), מותאם לטלפון, עם עגלה, פאנל ניהול בכתובת `/admin`, וסליקה באשראי דרך טרנזילה.

## מבנה הקבצים

```
index.html                    הדף הראשי
data/site.json                כל התוכן: מוצרים, טקסטים, צבעים, קישורים, הגדרות תשלום (נערך בפאנל הניהול)
templates/*.json              תבניות מוכנות (אופנה, טכנולוגיה, יופי, ריקה)
images/                       תמונות
admin/                        פאנל הניהול (index.html + config.yml)
result.html                   דף "תודה" / "התשלום נכשל" אחרי טרנזילה
netlify/functions/            שתי פונקציות שרת קטנות לתשלום
css/style.css, js/app.js      העיצוב והמנוע (לא חייבים לגעת)
netlify.toml                  הגדרות Netlify
```

## החלפת תבנית

מעתיקים את התוכן של אחד הקבצים ב-`templates/` (למשל `tech.json`) לתוך `data/site.json` ושומרים. כדי ליצור תבנית חדשה: מעתיקים את `blank.json`, ממלאים, ומשתמשים בה באותו אופן.

---

## 1. פאנל ניהול (`https://האתר-שלכם/admin/`)

הפאנל (Decap CMS) עורך את `data/site.json`: מוצרים, תמונות, מחירים, טקסטים, צבעים, קישורים ופרטי קשר, ושאלות נפוצות. כל שמירה בפאנל נשמרת כעדכון ב-GitHub ו-Netlify מפרסם אותה אוטומטית תוך כדקה בערך.

חשוב לדעת: ההתחברות לפאנל היא עם חשבון **GitHub**, ולכל מי שמנהל צריכה להיות גישת כתיבה (push) למאגר. אין מערכת משתמשים נפרדת.

### הגדרה חד-פעמית

1. **מאגר GitHub:** פותחים חשבון ב-github.com, יוצרים מאגר חדש (Private מתאים), ומעלים אליו את כל קבצי התיקייה.
2. **חיבור ל-Netlify:** ב-Netlify בוחרים Add new site > Import from Git ובוחרים את המאגר. Build command ריק, Publish directory `.`
3. **עריכת `admin/config.yml`:** משנים את השורה `repo: YOUR-GITHUB-USER/YOUR-REPO` לשם המאגר שלכם (בפורמט `שם-משתמש/שם-מאגר`). אם הענף שלכם נקרא `master`, משנים גם את `branch`.
4. **התחברות עם GitHub:**
   - ב-GitHub: Settings > Developer settings > OAuth Apps > New OAuth App. בשדה Authorization callback URL כותבים `https://api.netlify.com/auth/done`. שומרים את ה-Client ID ויוצרים Client Secret.
   - ב-Netlify: Site configuration > Access & security > OAuth > Install provider > GitHub, ומדביקים שם את שני הערכים.
5. נכנסים ל-`/admin/`, לוחצים Login with GitHub, ומתחילים לערוך.

(שלבי ה-OAuth מבוססים על התיעוד של Decap ו-Netlify. אם הממשק ב-Netlify השתנה, חפשו "Netlify OAuth authentication provider".)

טיפ: תמונות מעלים דרך שדה התמונה בפאנל. מומלץ ריבועי, JPG או WebP, עד 150KB.

## 2. סליקה בטרנזילה

האתר מעביר את הלקוח לעמוד התשלום המאובטח של טרנזילה (DirectNG). פרטי האשראי לא עוברים דרך האתר שלכם.

> שימו לב: האינטגרציה הישנה של טרנזילה (`direct.tranzila.com`) מסומנת בתיעוד שלהם כמוצר שהתמיכה בו מסתיימת ב-1 בינואר 2027. האתר בנוי על הכתובת החדשה `directng.tranzila.com`.

### הפעלה (בלי נעילת סכום)

ב-`/admin` (או ישירות ב-`data/site.json`):

1. **איך מתקבלות הזמנות** = "תשלום באשראי דרך טרנזילה" (`"checkout": "tranzila"`)
2. **שם מסוף טרנזילה** = שם המסוף שלכם (`"tranzilaTerminal"`)
3. בהגדרות המסוף ב-MY.TRANZILA מוודאים שמסוף ה-DirectNG / iframe פעיל אצלכם. אם עמוד התשלום מבקש שדות נוספים שחסרים, פנו לתמיכה של טרנזילה.

מה קורה: הלקוח ממלא פרטים, ההזמנה נשמרת אצלכם ב-Netlify Forms (Forms בלוח הבקרה של האתר), ואז הוא עובר לתשלום. אחרי התשלום חוזר לדף תודה.

**חולשה במצב הזה:** הסכום נשלח מהדפדפן, ולכן לקוח טכני יכול לשנות אותו ולשלם פחות. לכן, לפני שמסמנים הזמנה כשולמת ושולחים סחורה, משווים את הסכום ב-MY.TRANZILA לסכום בהזמנה. דף התודה הוא הודעה ללקוח בלבד ואינו אישור תשלום.

### הפעלה מאובטחת (נעילת סכום, מומלץ)

טרנזילה מציעה מנגנון Handshake שנועל את הסכום בשרת שלה, כך ששינוי בדפדפן נחסם. הוא דורש **רכישת מודול Token בחשבון טרנזילה** והפעלת Handshake בהגדרות ה-iFrame של המסוף (פנו לתמיכה שלהם). האתר כולל את הפונקציה `netlify/functions/handshake.js` שמחשבת את הסכום מהקטלוג בשרת ומבקשת את הנעילה.

1. בטרנזילה מקבלים מפתח ציבורי (App Key) ומפתח פרטי (Secret) של ה-API.
2. ב-Netlify: Site configuration > Environment variables, מוסיפים `TRANZILA_APP_KEY` ו-`TRANZILA_SECRET` (המפתח הפרטי סודי: לא בקוד ולא ב-GitHub).
3. בפאנל מסמנים "נעילת סכום מאובטחת מול טרנזילה" (`"secureHandshake": true`).

**חשוב לבדוק לפני עלייה לאוויר:** חתימת הבקשה לטרנזילה נכתבה לפי תיעוד שלא מפרט במפורש איזה ערך הוא המפתח ואיזה ההודעה. מימשתי את הקריאה הנפוצה (HMAC-SHA256, מפתח = סוד + זמן + nonce, הודעה = המפתח הציבורי), אבל לא יכולתי לבדוק אותה מול טרנזילה. בצעו עסקת בדיקה אחת. אם מתקבלת שגיאת הרשאה (Unauthorized), בקבצי `handshake.js` מחליפים בין המפתח להודעה בפונקציה `authHeaders`, או מבקשים מטרנזילה את דוגמת הקוד שלהם.

### בדיקה לפני עלייה לאוויר

עושים עסקה אחת קטנה (כרטיס אמיתי בסכום נמוך, או מסוף בדיקה אם טרנזילה סיפקה) ומוודאים: (1) עמוד התשלום נפתח עם הסכום הנכון, (2) אחרי תשלום חוזרים לדף התודה, (3) ההזמנה מופיעה ב-Netlify Forms, (4) העסקה מופיעה ב-MY.TRANZILA.

## 3. העלאה ועדכון

- **הדרך המומלצת:** GitHub + Netlify, כמו בסעיף הניהול למעלה. כל שינוי מתפרסם אוטומטית.
- גרירה ידנית ל-app.netlify.com/drop מתאימה רק לאתר בלי פונקציות. פאנל הניהול, ה-handshake והחזרה מטרנזילה דורשים העלאה דרך Git.

## 4. בדיקה מקומית

בתיקייה: `python3 -m http.server` ופותחים http://localhost:8000 (פתיחת הקובץ ישירות לא תעבוד כי התוכן נטען מ-JSON). פאנל הניהול והפונקציות עובדים רק ב-Netlify.
